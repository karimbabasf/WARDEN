# DOSSIER Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build DOSSIER — a longitudinal, evidence-cited operator profile with a research-grounded hybrid efficiency score and a token-driven activity heatmap — reading existing WARDEN data, writing only new `dossier_*` tables.

**Architecture:** New self-contained Rust module `src-tauri/src/dossier/` (one-purpose submodules), reached by new `#[tauri::command]`s. Deterministic aggregation does the heavy lifting; the GLM-5.2 brain is used only for cached per-session summaries, profile synthesis, and weight *proposals*. A full-page frontend surface lands last.

**Tech Stack:** Rust (Tauri v2), rusqlite 0.32, reqwest, tokio, chrono, serde, schemars; later `fastembed` + `sqlite-vec` + `linfa` (Phase 4); React + R3F frontend (Phase 7).

**Companions (read for every task):**
- Spec: `docs/superpowers/specs/2026-06-27-dossier-profile-by-proof-design.md`
- Rubric: `docs/superpowers/research/dossier-efficiency-rubric.md` (`RUBRIC_VERSION = dossier-rubric-v1`)

## Global Constraints

- **Isolation:** reads `sessions`/`turns`/`events`/`features`/`radar_token_cache`/findings; writes ONLY new `dossier_*` tables. NEVER write `habit_resolutions`, `sessions`, `turns`, `events`, `features`, `profile`, `findings`, `diagnoses`; NEVER call `set_habits_window`.
- **No shared-signature churn:** treat `featurizer.rs` / `detectors.rs` as read-only contracts (additive helpers only, never change existing signatures — Habits depends on them).
- **Windowing convention:** scope by `since: Option<DateTime<Utc>>` (reuse `store.features_since(since)`, `store.findings_since(since)`, `detectors::nominate_windowed(store, profile, since)`). Do NOT add a `window` field to `RunScope`.
- **Reproducible score:** deterministic sub-scores combined with weights **pinned** in `rubric.rs` from `RUBRIC_VERSION = "dossier-rubric-v1"`. The LLM may *propose* revised weights (pinned as a new version before use); it never rolls the live number. Headline score is always shown with its sub-scores.
- **Efficiency is a ratio:** `token_burn_total` is NEVER a standalone negative (per rubric outcome signal). High burn + verified work + low rework = good.
- **Privacy:** on-device only; the sole egress is the existing brain (NEAR AI), and only compact aggregates/summaries/evidence — never raw transcripts.
- **Green gate per task:** `cd src-tauri && cargo test` passes; frontend tasks also `pnpm build`. Evidence before "done."
- **Harness reality:** `Harness` is `ClaudeCode | Codex | Cursor | Hermes | Generic(String)` — heatmap/splits must handle all via `harness.as_str()`, not assume two.

## Phases 2–7 (roadmap — detailed when reached)

- **Phase 2 — Efficiency scoring engine.** `rubric.rs` (the 7 families + normalization + pinned v1 weights from `dossier-rubric-v1`, summing to 1.000), `efficiency.rs` (per-session family sub-scores → window headline, all 0..1, reproducible), `get_efficiency_score(window)`. Golden reproducibility test: same fixtures + same `RUBRIC_VERSION` → identical score. **Phase 2a (empirical pass):** mine the real corpus to answer the rubric's 9 open questions (per-subagent token attribution, percentile-vs-absolute thresholds, `context_saturation_peak` true-peak, commit/test-pass markers); record findings, adjust normalization, bump `RUBRIC_VERSION` if weights change.
- **Phase 3 — Hierarchical summarization + caching.** `summarize.rs` per-session micro-summary (cached forever in `dossier_session_summaries`, keyed by `session_id`+`raw_hash`+summarizer_version) → per-week/project rollups. LLM stages live in `brain.rs` reusing its private `send_chat_completions` / `extract_chat_message_content`.
- **Phase 4 — Embeddings + clustering + archetypes.** Add `fastembed` + `sqlite-vec` (+ `linfa`); `cluster.rs` for project archetypes + semantic dedup of recurring patterns; `dossier_embeddings` table (cached by content hash). Degrade to a signal heuristic if embeddings underperform.
- **Phase 5 — Synthesis + by-proof + trajectory.** `synthesize.rs` (GLM-5.2 → structured `Profile`: 7-dimension narrative + ranked leaks + proposed weights), `proof.rs` (≥N-evidence gate, trend sample-size gate, downgrade to "emerging"), `trajectory.rs` (per-trait trends from time bins + `profile_history`).
- **Phase 6 — Persistence + commands + events.** `dossier_profiles` cache (keyed by `window`+`data_hash`), `build_profile(window)` (emits `dossier_progress`) + `get_profile(window)`, degradation/detector-only mode.
- **Phase 7 — Full-page Profile surface.** New full-window instrument in `src/viz/` (alongside the Habits/Radar switcher), wired via `bridge.ts` (`SceneState.profile` already exists); efficiency score + sub-scores + heatmap (per-harness hover) + 7-dimension report + window toggle. Functionality first; aesthetic pass deferred.
